## Data rules (the app's promise)
- The App Store build ships **no Google-derived data**. `CO_APP=1` switches `pipeline/colorado.py` into that mode and writes `data/app/places.json`.
  Copy it to `ColoradoEats/Resources/places.json` after every rebuild (a unit test fails if rating/review/price fields appear).
- Inspections: **Boulder County only** (data.colorado.gov `6ytb-f2cq`; `rec_date_1` is the inspection date, `rec_date` the record's creation).
  Show the recorded result (Pass / Re-Inspection Required / Closure) and points, never a grade of ours: Closures appear at 20 and 42 points.
  The tiers come from CDPHE Interpretive Memo 19-09 under C.R.S. 25-4-1607.7 (not from rule 6 CCR 1010-2). The 2013–2025 archive (`tuvj-xz3m`)
  uses different facility ids for different businesses: join by name and address, never by id.
- Every other county's inspections are search-only portals (several bot-protected): never scrape them. Bulk extracts or CORA requests need Nick's yes.
- The Green Chile, Game & Steakhouses and Ski Town Dining guides list only **hand-checked** places (`hc`, research in `data/research/app/*.json`
  with a 2025–26 source). Brewpubs = an active state Brew Pub or Distillery Pub license. "Opened" means at this address.
- Website links: `pipeline/check_websites.py` (polite, honest UA, resumable). Re-run it before each submission, then rebuild with `CO_APP=1`.
- Places the research finds closed go in `data/research/closed.json` or `data/research/app/closed_*.json` with a source.

## Build the app
- The Xcode project is **generated**: `xcodegen generate`. Never commit `ColoradoEats.xcodeproj`.
- Simulators: **"CO Eats 6.9"** (iPhone 17 Pro Max, `AD345F00-BB20-4CF6-B812-878990469941`) and **"CO Eats iPad 13"** (`3B22DCFD-628B-425D-A6B9-51C3317B5997`),
  iOS 27.0, plus **"CO Eats SE"** (`20687CC1-A221-48E9-BEAB-1774364B3017`) for large-text checks. One booted at a time; shut it down when done (`xcrun simctl shutdown <udid>`); check `ps -u $(id -u) | wc -l` (< ~2,300) before booting.
  Never touch other sessions' simulators.
- Build: `xcodebuild build -project ColoradoEats.xcodeproj -scheme ColoradoEats -destination 'id=<udid>' -derivedDataPath ./DerivedData CODE_SIGNING_ALLOWED=NO`
- Unit tests: same with `test -only-testing:ColoradoEatsTests`. UI smoke test: `-only-testing:ColoradoEatsUITests` **without** `CODE_SIGNING_ALLOWED=NO`.
- Screens: `-screenshot <home|greenchile|honors|detail|map|brewpubs|ski|oldest|saved|about>` (DEBUG builds only; fixed location downtown Denver).
  `scripts/capture-screenshots.sh "<udid>"` writes `docs/screenshots/`; `PREFIX=ipad-` for the iPad set.
- **App Store builds come from the public Xcode**: `DEVELOPER_DIR="/Applications/Xcode 1.app/Contents/Developer"` (27.0); `Xcode.app` is a 27.1 beta.
  Check `DTXcodeBuild` in the archive; bump `CURRENT_PROJECT_VERSION` for every upload.
- `ColoradoEats/Resources/PrivacyInfo.xcprivacy`: UserDefaults CA92.1, no tracking, no collected data.
- Lessons from the first build (2026-10-05):
  - The map's "town zoom" is judged by the narrower side (`MapScreen.townSpan`): the iPad's tall, narrow middle column stretched the
    latitude span past 0.3° at town zoom, so "My location" never filled in the Everything layer there (iPhone was fine).
  - "My location" ignores cached fixes from before the tap (`LocationService.askedAt`).
  - UI tests match Home cards with `guideCard(_:)`: "Surprise me with a green chile spot" also contains "green chile".
  - Never dump `app.staticTexts.allElementsBoundByIndex` with the map filled in: hundreds of pins make the query time out.
  - The Honors list is ordered by MICHELIN distinction, then James Beard honor, then name, with no points shown (they read like a rating).
